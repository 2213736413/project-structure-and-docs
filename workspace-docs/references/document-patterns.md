# 写作指南

按任务选用相应部分。缺少证据时，保留待确认项并说明如何验证。

## 参考规范

1. **文档状态与范围**。标记参考稿、待评审或已采用。列出适用系统、读者和例外边界。只有用户或现行规则明确确认后，才标记为已采用。
2. **条款**。每条写清触发条件、预期行为和可观察的验收方式。区分必须、建议和可选。把由团队决定的参数或策略列为待确认项。
3. **示例与例外**。至少覆盖关键规则的正常路径和边界情况。涉及接口时，可提供请求、响应及失败样例。
4. **采用与验证**。说明如何在新项目启用、如何处理存量行为，以及通过哪些测试或审查验证。

幂等参考规范可以用两次相同请求验证是否只产生一次业务副作用，并单独定义同一个键携带不同请求体时的行为。键的保留期、冲突响应和适用接口由团队确认。

## 发布与运维手册

| 小节 | 写明 |
| --- | --- |
| 触发和适用范围 | 操作目的、目标环境、服务、版本，以及应中止的条件 |
| 前置检查 | 执行位置、账号权限、配置来源、依赖状态和可用回滚点 |
| 执行步骤 | 命令或控制台操作、参数含义、影响范围、可重试的步骤和重复执行风险 |
| 成功验证 | 检查项、预期信号或阈值、观察窗口及结果记录位置 |
| 失败和回滚 | 触发阈值、停止点、回滚步骤、数据兼容约束以及回滚后的验证 |

命令注明验证状态和适用环境。文档编写任务中，优先用现有脚本、配置和历史记录核对命令。生产环境操作须有任务授权。

## 其他常用文档

- **知识笔记**。用一句话回答问题，再给适用边界、示例和原始来源。读者可以直接跳到结论。
- **实验记录**。记录模型或代码版本、数据集版本、配置、评测口径及基线。关键结果链接原始产物，失败样例单独说明可复现条件。
- **发布记录**。保留实际版本、环境、变更范围、验证结果和回滚点。
- **排障记录**。按时间记录观察和排查动作。区分假设与确认根因，补充修复验证及相关发布或手册链接。
