# 归档与迁移

## 盘点

- 列出任务范围内的目录、索引、主文档、附件和导出件。查找当前路径、文件名及旧标题在 Markdown 链接、图片引用、索引和站点导航中的出现位置。检查同名目标和已有用户改动。
- 比较重复文档的读者、适用版本、环境和来源。优先沿用正式入口或已经被引用的主文档。两个版本的约定冲突时，记录差异及来源，待确认生效版本后再合并。
- 对每组文件确定动作和理由。动作包括就地更新、整组迁移、合并、归档或保留。归档时保留原项目或话题的上下文。

## 执行与复核

1. 先列出旧路径到新路径的映射，包含配套附件。存在同名冲突时，按版本、用途或日期区分，并保留原有内容。
2. 按组移动，更新指向旧路径的引用，并重算移动文件内的相对链接。正文、图片和导出文件可分别位于同一项目的子目录。
3. 逐一验证受影响的索引入口、相对路径、图片和改过的标题锚点。用旧路径和旧文件名搜索遗漏。站点导航或发布流程引用了旧路径时，按仓库约定验证对应入口。
4. 报告最终路径和需要确认的冲突。无法从当前工作区核实的外部引用单独列出。

## 示例

一次模型服务上线后触发延迟告警。把该次发布记录、告警证据和排障结论归到模型服务项目，互相链接。通用的发布验证手册仍放在部署话题下，项目发布记录补充本次镜像版本、阈值和回滚点。移动项目排障记录时，同时修复项目索引中指向该记录的入口，以及记录里指向监控截图的相对链接。
